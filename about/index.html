How I Work

Engineering decisions start with the problem.

01

Understand the actual problem

Before changing code, I want to understand the business requirement, current behavior, constraints, and where the actual bottleneck exists.

02

Measure before optimizing

Performance work should be driven by evidence. Slow queries, unnecessary database calls, and expensive operations should be identified before changing the implementation.

03

Keep complexity intentional

Architecture should solve real problems rather than add ceremony. I prefer clear boundaries, explicit dependencies, and predictable data access.

04

Build for the next engineer

Production software lives longer than the person who originally wrote it. Readability and maintainability are therefore part of the engineering job.
